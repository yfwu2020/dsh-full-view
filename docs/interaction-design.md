# 完整视图的交互设计与 DSH 适配

本页描述 **main 分支尚未发布的实现**。已发布 npm / GitHub Release 仍为 0.1.4；普通提交不会发布。

## 参考依据与验证范围

参考了用户提供的两张 Codex 真实截图，以及本机安装版本的浮动聊天、缩放和右面板输入条实现。截图确认了紧凑输入条、展开操作栏、标题和拖动入口的呈现；静态代码确认了状态切换、焦点保护、外部点击、拖动取消、缩放和恢复入口的行为。

当前自动化工具禁止操控 Codex 自身窗口，因此这里是**截图与静态实现核对**，不是 Codex 现场交互实测。参考代码没有复制进插件。以下 DSH 行为由本仓库独立实现，自动测试与浏览器验证页提供交互证据；真实 DSH 桌面自动点击仍无法定位窗口，完整桌面复核尚待完成。

## 状态与操作

| 参考交互 | DSH 实现 | 适配原因 |
| --- | --- | --- |
| 默认紧凑输入 | 默认只显示原生输入条 | 遵循用户选择，保留草稿、附件和发送逻辑 |
| 输入聚焦、拖动或菜单打开时揭示操作栏 | 在上述条件下显示标题及操作；另支持鼠标悬停 | 让收起、隐藏、返回分栏在紧凑状态也可发现 |
| 点击标题切换紧凑 / 展开 | 标题、外缘和减号均可切换 | 操作栏出现不等于展开全部消息 |
| 点击浮窗外部自动收起 | 收回输入条，包含点击预览 iframe | 把空间还给工作内容，保留输入能力 |
| Esc 收起展开的聊天 | 焦点位于聊天内时生效 | 原生菜单、输入法及宿主已处理的按键优先 |
| 拖动入口、边缘拖动 | 顶部点状手柄、标题空白和外缘可拖动 | 不劫持文字编辑、选择和原按钮操作 |
| 停靠和吸附 | 松手时靠近工作区四边 24px 内吸附 | 保留 DSH 自由摆放，不引入宿主没有的全局停靠服务 |
| 拖动取消 | Esc、指针取消、丢失捕获、窗口失焦均恢复起始位置 | 取消时不覆盖已保存的尺寸 / 位置 |
| 多方向缩放 | 展开后四边和四角可缩放；紧凑时左右边调宽 | 西 / 北边缩放保留对边锚点，角落不显示角标 |
| 复位 | 双击边缘 / 角落恢复配置尺寸，双击标题恢复默认位置 | 标题和直边单击等待 260ms 区分双击；角落单击不收起 |
| 缩小成可恢复入口 | × 隐藏聊天，工作区保留“打开聊天”按钮 | 按钮在隐藏聊天之外，原聊天 inert，恢复后聚焦原编辑器 |
| 未读与回复入口 | 收起 / 隐藏时会话内容变化显示“有新内容”；点击查看原会话 | 不复制富文本、不把工具更新或历史加载误称为模型新回复 |
| 受限视口内的位置调整 | 观察工作区、导航栏、输入条及 visualViewport | 缩窗、页面缩放或软键盘出现时保持可见，不覆盖原尺寸偏好 |
| 动画与减弱动态效果 | 进入时淡入；圆角 160ms；位置与尺寸直接更新，reduced-motion 下关闭动画 | 避免悬停揭示标题时输入框命中位置漂移，照顾系统动态效果设置 |

## DSH 特有的约束

审批使用 `data-approval-key`，用户提问使用 `data-question-key`，计划确认使用 `data-plan-review-key`。检测到当前会话的这些面板时自动展开，暂时禁止收起 / 隐藏；处理完成后恢复之前状态。宿主用其他组件替换整个输入区时，优先展示完整内容。

`data-conversation-composer-overlay` 属于轨迹视图，不能用它判断待审批。内嵌子会话的输入框和待办也不应抢走当前会话的状态或焦点。

原生模型、权限、附件和其他弹出菜单继续使用宿主组件。检测到可见的原生菜单、对话框等覆盖界面时，暂停自动收起；插件的 Esc 监听在冒泡阶段运行，尊重 `defaultPrevented`、`isComposing` 和输入法兼容键值。

不足 320px 宽时，输入框占第一行，原按钮分列到第二行。多行草稿和附件仍会自然增高。命名容器查询避开原生控制行自己的容器定义，防止按钮被输入区域盖住。

## 键盘与生命周期

外缘按钮支持 Enter / 空格。顶部拖动手柄和隐藏后的恢复入口支持方向键移动；缩放区域支持方向键调整其对应轴；Shift 加大步长。查看新内容或恢复聊天后聚焦原编辑器。收起不重建编辑器，也不写入草稿。

退出分栏、关闭面板、插件停用或热重载会移除工具栏、恢复入口、更新提示、临时属性、计时器、事件监听及观察器；还原宿主原有 inert / aria-hidden。只将几何偏好写入 localStorage，不另外存储消息或草稿。

## 本轮没有复制的宿主专属功能

Codex 的跨会话选择、模型运行状态服务、富文本完成预览及系统浮窗穿透依赖其宿主服务。DSH 当前适配使用原会话和原组件，没有虚构这些服务。新内容入口只引导用户回到原消息；是否运行、完成和审批继续以 DSH 原生状态为准。

设计目标是迁移可验证的操作方式，并保持 DSH 的会话和输入能力完整。真实桌面菜单组合、其他操作系统与其他 Harness 版本仍需继续验证。
