# 配置和适配说明

普通使用者无需修改以下配置。通过 Harness 的标准 bundle 机制加载插件；管理页的启停选择是插件是否加载的依据。

## 配置

| 字段 | 默认 | 范围 / 含义 |
| --- | --- | --- |
| chatWidth | 400 | 280–800，初始宽度，像素 |
| chatHeight | 540 | 240–1000，初始高度，像素 |
| edgeGap | 20 | 0–64，与工作区边缘的间隔，像素 |
| rememberGeometry | true | 在浏览器 localStorage 中记录窗口几何信息 |

实际尺寸限制在可见工作区内。记录的几何信息会优先于初始尺寸；双击右下角可恢复配置尺寸并保留当前位置，双击标题栏可恢复配置尺寸和默认位置。若当前位置无法容纳恢复后的尺寸，会调整位置以保持小窗可见。

配置由宿主入口校验，经 `/dsh-full-view/api/config` 传给客户端。非法配置在加载时拒绝。插件卸载后移除该路由。

## 适配范围

宿主加载 `lib/index.js`，客户端通过 `window.__ModuleLoader__` 加载 `lib/client.js`。客户端依赖 `layout` 和 `sidebarRight` 服务。

适配器通过 `data-rightbar-col`、`data-rightbar-fullscreen`、`data-sidebar-right-panel` 等语义标记找到原聊天容器，并检查会话身份匹配。它改变原聊天容器的定位，不重建会话、编辑器或 iframe。返回分栏使用面板自身的按钮。

宿主更改上述标记或相邻结构时，需要更新适配器。目前针对 layout / sidebar-right 0.2.0-rc.2 验证；未支持旧源码中的 details 布局。

小窗层级为 50，在原工作面板之上、DockKit 原有浮窗层级 60 之下。宿主菜单及审批弹窗仍由宿主管理，尚未完成所有弹窗组合的交互验证。

卸载和热重载会清理插件的工具栏、样式、几何标记、事件与观察器，保留宿主原有内容及布局状态。
